# 真人测试与异机验收

## 一、当前证据与范围

固定120题是开发中已经使用的合成回归集，不是盲测。词法、混合、独立重排的严格答复／引用结果见`docs/assets/评审修订RAG验收.json`。真人问法由真实参与者提供，禁止用模型代填或复制120题，失败不得删除。自动导入工具只核验格式和声明，不能证明参与者身份、现场操作或听觉效果。

## 二、真人RAG测试（约40分钟，建议5人各8题）

1. **准备（负责人5分钟）**：冻结当前源码ZIP的`SOURCE_MANIFEST.json`、知识库与模型版本。使用新的测试数据库，默认离线；本地向量/重排资产准备齐全后再测完整AI模式。记录日期，因为过期产品卡必须拒答。不要用日常数据库。
2. **自然提问（参与者10分钟）**：为每人分配`p_`加4—16位字母数字的匿名编号。只告知系统支持项目规则解释和两种公开存款资料；不先给标准答案或120题。每人自行写8个问法：4个日常问题、2个资料未覆盖问题、1个容易混淆的授权／成功状态问题、1个自然改写。不得包含真实姓名、手机号、卡号、证件、密码或密钥。RAG导入器会拒收攻击指令；注入攻击使用既有本地专项测试另记。
3. **独立标注（两位其他成员10分钟）**：先读冻结知识卡，为每题标注`expected_type`和`relevant_ids`。可答用`answerable`及一个或多个来源ID；无资料用`uncovered`且ID为空；办理请求或账户事实用`out_of_scope`。两人分别判断，有分歧先保留，讨论确定后才进入汇总；不要看检索排名再修改标签。
4. **现场验证（10分钟）**：在页面选择知识问答，每题输入一次，保留完整答复、引用来源、实际状态、耗时及是否需要提示帮助。检索到相关资料而答复不正确，仍判失败。页面只展示当前配置的一种模式；三模式对比由离线评测命令完成。
5. **登记与复跑（5分钟）**：复制`eval/rag_user_study_template.json`到私有验收目录，填入真实样本。每项字段为`participant_id`、含时区的`submitted_at`、`question`、`relevant_ids`、`expected_type`、两名不同复核者的`reviewers`。`consent_local_processing`只有取得参与者同意才设为`true`。不要把真实样本提交到公开GitHub。

在项目根目录运行（本地模型及可选依赖必须可用）：

```powershell
python scripts/rag_evaluation.py --dataset eval/rag_eval_v4.json --user-study data/verification/human-rag/samples.json --output data/verification/human-rag/result.json
```

`by_split.human`单独报告真人结果；不要与120题合并成“真人准确率”。另记录正例首位来源命中率、正确拒答率、答复/引用正确性、需要帮助比例和失败清单。空模板应保持`PENDING`。

## 三、真实业务／硬件验收（约25分钟）

使用虚构账户和隔离数据库启动，不能用真实资金：

```powershell
$env:BANK_AGENT_OFFLINE='1'
$env:BANK_AGENT_HOST='127.0.0.1'
$env:BANK_AGENT_PORT='8095'
$env:BANK_AGENT_DB_PATH=Join-Path $env:TEMP ('yinban-human-'+[guid]::NewGuid().ToString()+'.sqlite3')
python app/banking_agent.py
```

本机浏览器打开`http://127.0.0.1:8095`。需要完整AI时另按部署说明配置本地模型、依赖和选项；上述命令本身不证明资产完整。逐项记录成功／失败、时间、是否有人提示；不办理真实业务：

| 项目 | 真人动作 | 通过标准 |
|---|---|---|
| 三色与再次确认 | 查询余额、小额转账、高风险转账，核对确认卡 | 查询无资金副作用；黄色先确认；红色按原链验证；确认不冒充银行成功 |
| 订阅与卡片 | 查看订阅、取消未来扣款、查看卡片并验证确认 | 服务权益／扣款／退款分开；取消或卡片操作不绕过权限 |
| 生日联动 | 自行指定鲜花、蛋糕的提前时间 | 草稿与用户指定时间一致；每个步骤可查看状态 |
| 人工接管 | 两个窗口分别作为用户和坐席，发送／回复固定无隐私文本 | 对方确实收到；领取／结单有审计；结单不执行转账 |
| TOTP | 自建身份模式，使用另一台设备的独立验证器 | 正确码成功，错误／过期码失败；不能用演示固定验证码替代 |
| 麦克风／OCR／读屏 | 现场录音、真实拍照样本、NVDA或VoiceOver | 识别后人工核对；低置信度不自动执行；键盘/读屏能读出确认与错误 |

默认离线不会调用云ASR。云端语音发送需按已有同意流程明确确认，不能把这次离线测试称为云端验收。真人业务记录参考`eval/prototype_user_study_template.json`，至少两名其他复核者；工具`scripts/prototype_user_study.py`的结果仅为声明校验。

## 四、原生PPT与视频（约10分钟）

1. 在PowerPoint/WPS打开最终PPTX，从首页开始放映，检查中文字体、架构图、表格、页码和溢出；用手机秒表汇报，含视频时总计不超过10分钟。
2. 用Windows媒体播放器或实际答辩播放器完整播放MP4，不拖进度条，核对声音、字幕与操作画面、首尾、黑屏和卡顿，记录播放器名称/版本与视频SHA256。
3. COM打开／导出或静音自动播放只能证明对应技术动作；不能替代上面两项真人结论。视频若未重新录制，不声称展示了最新检索分数。

## 五、回环绑定与评委访问

- `127.0.0.1`指运行应用的那台电脑。评委把源码或离线包下载到自己的电脑并启动后，仍可打开本机地址；GitHub源码、PDF和视频可正常浏览。GitHub不是应用托管网站。
- `docker compose`需要Docker引擎；Python标准库文本演示不需要Docker。完整AI离线镜像必须先构建、导出并验证，单有源码ZIP不包含本地模型和运行环境。
- 别的电脑不能通过你的`127.0.0.1`访问你电脑。优先让评委在演示电脑观看或在其电脑启动副本。不要为匿名远程浏览直接把演示认证暴露到公网。
- 若确需同一局域网临时展示，由操作者显式调整监听/端口映射及防火墙，并使用隔离虚构数据；这不是当前默认方式，也不等于公网生产部署。

## 六、物理第二台电脑离线验收（约20分钟，不含导入）

1. 首机交付源码ZIP及同版完整AI离线包、`RELEASE_INDEX.json`、`SHA256SUMS`。核对源码快照与镜像内源码一致；旧镜像不能当新版本。
2. 第二台预备兼容Linux/amd64 Docker引擎，复制文件后断开外网。先核验文件SHA256，再按包内`START_HERE.md`执行`docker load`及`up --no-build --pull never`，不得临时拉取资产。
3. 访问第二台自己的回环地址，检查健康状态；现场输入未预置的知识问题，确认本地向量与重排确实工作，检查OCR及一条转账确认链，重启后检查任务/审计。仅同机换目录复验不能记为物理异机。
4. 记录匿名机器编号、系统/CPU架构、Docker版本、快照、镜像摘要、断网方式、操作时间、每项结果、两位复核者。缺引擎、缺模型或镜像未重建时写`BLOCKED`，不得写通过。

本轮若Docker引擎不可达，完整AI镜像与物理异机均保留待验；源码与本机检索通过不能替代这两项。
