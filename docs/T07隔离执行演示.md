# T07 隔离执行演示

## 要求与当前范围

原始赛题《人工智能赛道原始要求.docx》“三、核心技术要求”的沙箱条目（正文第 53 段）要求生成代码在受限、可监控的逻辑隔离环境运行。内部设计 `docs/安全设计与威胁模型.md` 第 6 节要求无网络、只读根文件系统、资源配额、库/函数白名单、结构化回传、代码与镜像摘要审计。

本批提供**运维脚本可重复运行的 Docker 隔离演示**。验收程序提供代码片段，未调用真实 LLM；不据此宣称模型生成质量或任意敌对代码的生产隔离已经通过。日常金融业务继续使用原有固定工具与 `PolicyEngine`，本批不新增银行业务权限，不向聊天开放代码/路径/镜像参数，不挂载 Docker socket 到银行应用容器。

## 运行与结果

先准备已启动的 Docker Linux 引擎和受信本地 `python:3.12-slim` 镜像。在项目根目录运行：

```sh
python scripts/sandbox_qa.py
```

脚本只读取已有镜像，不自动联网拉取。缺少 Docker、Linux 引擎或本地镜像时返回失败，不降级为宿主机执行。

验收包括：合成整数分金额计算 `result = sum([1200, 3400, 5600])`、导入拒绝、除零异常、环境隔离、超时终止、输出限制、内存限制、累计失败熔断。结果、独立审计数据库和每条 trace 的哈希链校验保存到 `data/verification/t07-docker-*/`。合成计算结果不代表真实账户或交易事实。

## 隔离与授权边界

| 边界 | 实现与核验 |
|---|---|
| 代码白名单 | 一条 `result = ...`；整数常量、有限列表/元组、加减乘/整除/取模、正负号、`sum/min/max/len/abs`；最大 4096 字节、256 AST 节点、16 层深度、64 个序列元素；拒绝浮点、字符串、导入、属性、文件、网络、shell、反射和循环 |
| 真实执行位置 | 独立容器内 `python -I -S -B`；宿主机只解析 AST 和组装命令，不使用 `eval/exec` 执行提交代码 |
| 镜像 | 先检查本地镜像平台，取得不可变 image ID，再按该 ID 创建；`--pull never`；禁止镜像声明的额外卷 |
| 身份 | 数值 UID/GID `65534:65534`、丢弃全部 capabilities、`no-new-privileges`；环境探针读取进程状态验证非 root、无能力、禁止提权、seccomp 过滤 |
| 文件与网络 | `--network none`、只读根文件系统；无主机卷/项目/银行数据库/socket 挂载，无端口映射；固定探针验证根目录写入和外连被拒绝、银行数据及凭据缺失 |
| 资源 | 64 MiB 内存且禁止额外交换、0.5 CPU、32 PID、64 KiB `/dev/shm`；核验 Docker 配置和 Linux cgroup v2 实际限额；内存探针触发 OOM |
| 时长与输出 | 默认 3 秒执行监控期限（包含附着启动开销），超时请求终止；Docker 控制与清理另有超时，清理失败不计通过；最多保留 8192 字节输出，超限请求终止；继续丢弃并排空剩余管道以避免 Docker 客户端阻塞；禁用容器磁盘日志 |
| 回传 | 普通计算只接受单个结构化 JSON 整数结果且处于安全整数范围；异常/超时/OOM/输出超限/清理失败不计成功 |
| 审计 | 注入现有 `AuditStore`；记录提交源码与镜像摘要、接受结果的规范化摘要、输出字节数、状态、清理状态和调用方；不保存源码全文、原始容器输出或凭据；摘要以字节列表保存，避免既有 PII 脱敏误改十六进制数字段 |
| 熔断与清理 | 复用独立 `CircuitBreaker`，失败累积达到既有阈值后锁定，无自动重试/解锁；正常或异常均只清理本次随机命名容器；审计起始记录失败则不执行代码 |

为核验 Docker 限额，脚本含固定的环境、无限循环、输出、内存探针。它们只允许按内置名称选择，不能由调用方替换源码，且不向日常业务入口开放。完整性测试与真实容器验收分开记录，不能用 mock 测试代替容器验证。

## 代码位置与交付限制

- `app/sandbox_execution.py`：白名单、Docker 隔离、有限输出监控、结构化结果、审计和熔断衔接。
- `scripts/sandbox_qa.py`：运维验收入口、独立演示审计、原数据库哈希核验。
- `tests/test_sandbox_execution.py`：拒绝和配额控制、不可降级、审计失效、摘要可还原、畸形输入、输出排空及熔断测试。

容器与宿主共享内核，此处是有限计算语法的竞赛演示。生产若允许更广泛的生成代码，应按原设计使用 gVisor/微型虚拟机等额外隔离，并评审租户身份、脱敏输入、供应链和安全测评。

Docker 仅是可选沙箱验收的外部前提，不新增 Python 第三方运行时依赖。准备 GitHub 离线发行包时，需同时交付应用镜像和本演示使用的基础镜像（含标签），并验证目标电脑支持 Linux 容器、相应 CPU 架构和 cgroup v2；本批未制作发行包。

Docker 参数依据：[官方容器运行参考](https://docs.docker.com/reference/cli/docker/container/run/)。
