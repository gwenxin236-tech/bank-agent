# E4 订阅三层治理与失败语义

## 1. 目标与边界

本演示把“取消代扣”“终止服务”“退款”拆成三个可分别核验的事实层，避免把一个模糊的“已取消”当成全部结果。当前事实来自离线 `MockBankCore`；它是生产核心/账单/代扣/服务商接口的替身，不代表已连接真实银行或服务商。

## 2. 三层模型

| 层 | 演示字段 | 用户看到的含义 | 生产替换点 |
|---|---|---|---|
| 交易层 | `transaction_layer.history` | 已发生的历史扣款、交易号、金额和结算状态 | 真实核心账务/支付流水查询；金额仍以整数分传递 |
| 授权层 | `authorization_layer.authorized_subject`、`debit_permission`、`terminable` | 谁授权了代扣、未来扣费权限是否停止、当前渠道能否处理 | 真实代扣协议与授权服务；由服务端权限策略核验 |
| 服务层 | `service_layer.member_status`、`valid_until`、`exit_conditions`、`refund_status` | 会员是否仍有效、到期时间、退出条件、退款是否已确认 | 真实商户/服务商订阅与退款接口；不能由模型猜测 |

取消成功后的演示结果是：授权层 `debit_permission=stopped`，服务层仍可能为 `active`，退款层为 `unknown`。因此**取消代扣 ≠ 终止服务 ≠ 退款**。未来少扣的钱不是现金入账，不进入余额或预算可支配金额。

订阅查询同时返回治理标记：`已确认订阅`、`疑似周期扣费`、`当前渠道可处理`、`需服务商处理`、`待核验`。标记是事实核验状态，不是风险诈骗结论。

## 3. 取消回执

计划卡在确认前先展示目标订阅、每期金额以及三层边界。执行后的成功回执分开展示：

- **停止未来扣费**：来自授权层工具结果；
- **服务有效期**：来自服务层 `member_status` 与 `valid_until`；
- **退款金额与状态**：来自服务层退款事实；`unknown` 只能显示“退款状态待核验”，不能说“已到账”。

回执中的数字只来自工具返回值。重复提交同一个幂等键返回同一笔取消结果，不再产生第二个副作用。

## 4. 故障语义

取消接口遇到演示故障 `transport_timeout` 或 `network_unreachable` 时：

1. Mock 核心不改变订阅授权、服务或退款状态；
2. 返回 `status=unknown` / `outcome_unknown=true`，不伪造成功；
3. 用户看到“取消结果待处理”，而不是“已取消”或“已失败”；
4. 审计追加 `subscription.unknown`，保留订阅标识和幂等键；
5. 不自动重试副作用。生产系统应查询原取消请求/服务商工单的最终状态。

## 5. 可信边界与验收

- 订阅金额全程使用整数分；
- 查询是只读操作，返回深拷贝，不会修改账户；
- 订阅查询按原始赛题“三、核心技术要求”的黄色权限行执行：`subscription_query` 进入黄色分组，先展示查询计划、获得明确确认，再调用 `list_subscriptions`，无需强认证；只读不等于可以自动执行。依据：`config/policy.json` 的 `yellow`、`app/policy_config.py::load_policy`、`app/banking_agent.py::PolicyEngine._base_classify` / `AgentRuntime.chat` / `confirm`。
- `tests/test_subscription_governance.py` 覆盖查询前不读取、确认后只读返回、审计、拒绝错误/跨计划/过期/取消/重复确认，以及查询工具失败；`tests/test_d1_security.py` 覆盖真实 HTTP 会话和确认绑定；`tests/test_d2_policy.py` 覆盖禁止配置降级及其他绿色查询不变。
- 取消权限和确认仍由既有 `PolicyEngine`、会话及计划确认链裁决，域工具仅提供只读说明适配器；
- `app/features/finance_health/` 的 `SubscriptionGovernanceTool` 只展示治理说明，不直接访问核心或执行取消；
- 生产替换前必须补充真实服务商身份、授权、退款核验、幂等、审计与灾备验收。

建议现场输入：`取消某视频会员，退款到账了吗`。应看到计划卡的三层说明，确认后看到“停止未来扣费 / 服务仍有效至具体日期 / 退款状态待核验”三态；注入超时后只显示“待处理”，订阅状态与账户余额不变。
