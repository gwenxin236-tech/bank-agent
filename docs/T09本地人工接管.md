# T09 本地人工接管闭环

## 对应要求与范围

《人工智能赛道原始要求.docx》正文第 23 段：“执行过程中支持中断、回退和人工接管”。本批按批准的本地演示方案，在既有接管卡、客服请求和 DAG 接管状态上增加坐席领取、固定结论、用户查询和持久审计，不改变银行执行权限或 Step 1 领域接口。

实现位置：`app/handoff_queue.py`；`AgentRuntime._create_handoff_card` 将既有交接卡登记到同一审计数据库，用户主动求助、人工门拒绝和未知结果接管沿用原入口。已有只生成历史交接卡的旧记录不会自动回填，可在本轮演示重新触发接管；不据旧卡推断工单已经存在。

## 状态与权限

| 状态 | 允许动作 | 身份 |
|---|---|---|
| LOCAL_QUEUED | 领取 → LOCAL_CLAIMED | 受信演示 admin 会话 |
| LOCAL_CLAIMED | 记录结论 → LOCAL_CLOSED | 原领取坐席及同一设备 |
| LOCAL_CLOSED | 查询；同结论重复提交返回原结果 | 工单本人/原坐席按接口权限 |

用户通过 `/api/v1/handoff/status` 只能查询本人同一设备的工单。坐席使用 `/api/v1/handoff/inbox`（每页最多 50，offset 翻页）、`claim`、`resolve`；全部为 POST，需要现有服务端 Bearer 身份，不能用消息中的 role 或 user_id 提权。客服请求 `/api/v1/customer-service` 现在也必须有可信演示会话。

结论只允许 GUIDANCE_PROVIDED（记录指引）、REFERRED_OFFICIAL（转官方渠道）、NEEDS_RECONCILIATION（仍需核对）；不允许自由文本、交易成功声明、改余额或重做原工具。未知结果接管只允许 NEEDS_RECONCILIATION；LOCAL_CLOSED 仅表示本地工单登记结束，不表示银行交易已结算、问题已解决或接通真人。

工单与 human.case.queued/claimed/closed 审计同事务提交，审计失败回滚状态；同来源交接重复登记返回原工单，领取和同结论结单支持幂等。不同坐席并发领取只有一个成功；领取后更换坐席设备拒绝。工单和领取设备跨进程重启保留，不自动重新执行银行副作用。坐席收件箱使用脱敏交接卡，不保存原始聊天、确认 token 或验证码。

## 用户与坐席操作

先在启动服务的可信 PowerShell 中生成仅供本地演示的随机管理令牌（不要写入源码、浏览器、Git 或聊天）：

```powershell
$env:BANK_AGENT_DEMO_ADMIN_TOKEN = [guid]::NewGuid().ToString('N') + [guid]::NewGuid().ToString('N')
python app/banking_agent.py
```

在继承相同环境变量的坐席终端中执行下列命令；第二个终端的变量需由操作者安全配置为同值。未配置管理令牌时没有默认坐席密码。服务读取环境变量发生在启动时，修改变量后需重新启动。

```powershell
python scripts/handoff_demo.py --action inbox
python scripts/handoff_demo.py --action claim --case-id case_替换为实际工单标识
python scripts/handoff_demo.py --action resolve --case-id case_替换为实际工单标识 --resolution REFERRED_OFFICIAL
```

浏览器点击“一键人工客服”，出现“查询本地接管进度”。领取/结单后点击查询，分别显示本地坐席已领取、已记录处理结论；查询失败明确显示无法核对，不自动重做业务。重复点击客服请求沿用现有 request_id，不自动创建新工单或重开已结单工单。

T18第2批增加“发起新一轮求助”：仅查询确认旧工单为 LOCAL_CLOSED 后启用，由用户主动点击生成新 request_id；新请求在发出前保存到同标签页 sessionStorage，响应丢失后普通客服按钮仍复用这个新标识，刷新后也可重试。排队/领取中、查询失败或新请求结果未知时不允许连续新建；旧工单不改、不重开，不恢复或重做银行交易。浏览器禁用存储时只能保持当前页面内的重试标识，不承诺跨刷新恢复。依据 `app/static/app.js` requestCustomerService / showLocalHandoffStatus / newSupportRequestBtn 监听器；`tests/test_handoff_queue.py::test_browser_user_can_observe_local_operator_closure` 覆盖真实环回 HTTP 结单、新轮、故意丢弃响应、同键重试及刷新后只有两个工单。

首页“显示与帮助设置”提供本地求助、服务记录/演示重置入口、安全中心、审计链回放、语音同意入口及显示偏好导航。仅隐藏卡片只影响设置内“本页卡片列表”，不改变银行状态、业务查询、转账核验或审计；来源读取失败不沿用旧列表。代码为 `app/static/index.html` / `app/static/app.js`，浏览器覆盖见 `tests/test_banking_flow_ux.py::test_settings_discovery_card_visibility_and_storage_failure`。未接真人客服等边界继续保留。

命令行客户端只允许环回 HTTP 地址，不跟随重定向、不自动重试、不输出 Bearer 令牌。输出为 ASCII JSON，避免 Windows CP936 输出货币/Unicode 符号失败。浏览器不包含管理令牌或坐席写权限。

## 验收与未覆盖边界

```powershell
python scripts/handoff_demo.py --qa
python scripts/browser_qa.py --full
```

第一条自动创建独立临时数据库、临时管理身份和环回 HTTP 服务，验证身份、排队、领取、结单、用户查询、幂等、非法成功声明拒绝、非空审计链和资金不变。记录在 `data/verification/t09-*/report.json`，正常数据库指纹必须不变。

`tests/test_handoff_queue.py` 另覆盖重启、越权、并发抢单、脱敏、审计故障回滚及未知结果不重提；其中浏览器用例检查实际点击查询、错误提示和 390px 无横向溢出，通过 full 命令启用。实测结果以本轮验收文件为准，历史测试数量不能当验收依据。

未接入真实客服、CRM、生产 IAM、坐席排班、SLA、通知供应商或银行核账服务。现有管理员角色仅用于本地演示，真实上线需要更细的坐席数据权限、身份验证与留痕审查；工单结单不会恢复已 handoff 的原 DAG。真实未知交易仍须独立对账，新业务仍须重新授权。
