# T08 本地第二渠道演示

## 要求与交付边界

《人工智能赛道原始要求.docx》正文第 8 段描述用户通过 APP、IM 等渠道与 Agent 沟通。本批按已批准的“多渠道先采用明确标注的本地演示级方案”实现第二种传输入口，不代表真实 IM 已接入或已满足真实平台接入验收。没有“至少三类渠道”的硬要求依据。

保留现有 Web，新增独立终端适配器 `app/local_channel.py`：本地 JSON 行 → LocalChannelAdapter → UnifiedMessage → AgentGateway → 原 AgentRuntime/PolicyEngine/工具/审计 → 本地回执。确认、验证、取消复用原 Runtime 方法。没有新增业务权限，没有外部发送服务、Webhook 或第三方依赖。

## 操作

```bash
python scripts/channel_demo.py
```

无需启动 HTTP 服务；每次使用临时离线 Mock 数据库，退出后清理，不读取或改动正常演示账户数据库。终端显示 `LOCAL_DEMO_ONLY`。操作者是受信本地演示身份 demo-user/demo-device；没有真实登录、真实客户身份或真实银行服务。

逐行输入 JSON：

终端回执使用 ASCII JSON（中文和货币符号保留为 Unicode 转义），避免 Windows CP936 无法编码 U+00A5 导致结果已执行却输出失败；按 JSON 解码可还原完整文本。

```json
{"message_id":"1","conversation_id":"demo","text":"查询余额"}
{"message_id":"2","conversation_id":"demo","text":"给妈妈转1元"}
```

第二条只返回黄色计划。用户审阅后，复制计划 `plan.plan_id` 与 `plan_view.action_token`，显式提交：

```json
{"message_id":"3","conversation_id":"demo","action":"confirm","plan_id":"复制计划ID","action_token":"复制token"}
```

红色计划先 confirm 得到 `auth_challenge.credential_id`，再提交 verify（相同计划与 token，加 credential_id、code），验证通过后以新 message_id、同一 credential_id 再次 confirm 执行。演示验证码 123456，不用于生产。取消用 action=cancel。每个新动作使用新 message_id，同一动作的重复投递使用原 message_id。

## 安全与限制

- 请求只允许已定义的字符串字段；身份、设备、角色、渠道和 metadata 不接受消息覆盖。身份映射由受信本地启动代码配置。此规则不是生产 IAM，也不代表公开终端可安全交给真实客户。
- 网关与有限草稿分别按渠道/身份/会话以及设备绑定；不沿用 Web 的转账草稿。不绕过反注入、权限分级或凭证消费。
- 每个适配器进程最多保留 1024 个事件结果，串行处理；同一身份与 message_id、相同内容返回缓存回执，不重新执行；内容变化拒绝；容量耗尽拒绝。返回深拷贝，避免调用者改写缓存。
- 结果不确定时保留失败回执，不自动重试副作用。去重仅在本地进程生命周期内有效；退出会清理本次数据，不提供持久化消息队列或跨进程交付保证。
- 业务审计复用现有 trace/哈希链；验收记录不保存 action_token、验证码或原始业务回复。交互终端会展示演示计划与令牌，请勿用真实身份、密钥或银行数据。
- `/api/chat` 中填 `channel=local_demo` 仅是 HTTP 元数据，不能替代本脚本实际终端适配器验收。能力列表表示可用入口，不是在线平台连接状态。
- 真实 IM 的签名/时戳/nonce、防重放、持久消息去重、IAM、发送失败与授权跳转仍未实现。本批没有真实平台发送证据；生产部署保持未就绪。

## 验收

```bash
python scripts/channel_demo.py --qa
python scripts/browser_qa.py --full
```

第一条执行本地适配器端到端验收，输出 `data/verification/t08-*/report.json`：绿色查询、会话隔离、黄级待确认、他人拒绝、确认扣款、重复投递不重做、已消费 token 拒绝、红级验证前不扣款、验证后仍不扣款、再次确认执行、防注入、非空审计链验证。原正常数据库指纹必须不变。

定向回归在 `tests/test_local_channel.py`，另覆盖并发重复、取消、错误验证码、身份伪造、缓存深拷贝、容量和异常不重试。实际通过数字以本轮生成记录为准，不能把文档历史数字当成验收依据。

2026-10-21 本轮实测：`data/verification/t08-20261021-210422-402546/report.json` 的 12 项检查通过，7 组非空审计链核验通过；`data/verification/t03-20261021-210531-429904/report.json` 完整回归 459 项通过、0 跳过、0 ResourceWarning，正常数据库指纹不变。另以原生编码子进程实测终端 stdin/stdout 查询成功。首次红色流程验收错误地期待 verify 直接扣款，已按原代码“验证后再次确认”修正验收，失败记录保留在 `t08-20261021-210349-890170`，没有因此改变业务权限。
