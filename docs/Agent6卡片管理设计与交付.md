# Agent 6：卡片管理设计与交付

成员：李苏润。基线：`0c6608f`。本域与订阅域分别评审；交付只包含自身模块、测试及本文。

## 用户与效果

依据项目用户研究第8节，服务需要安排日常资金、使用银行卡办理必要业务的个人用户，兼顾长辈和数字操作不熟练者。丢卡场景需要准确、简明的状态解释及明确下一步；找回卡片后也不能让用户误以为解挂必然恢复所有付款能力。

本域特色是“状态决定是否还需要操作，办理影响先解释，最终结果再核验”。评价以是否选错卡、是否重复建议、是否把未知说成成功以及是否保留认证为准；不把增加模型调用次数作为创新。

## 状态与操作设计

| 可信状态 | 请求 | 本域输出 |
|---|---|---|
| 正常 | 挂失 | 查询→挂失→核验候选；保留确认与 strong_auth；说明可能影响付款 |
| 已挂失 | 解挂 | 查询→解挂→核验候选；提醒确认卡已找回且本人保管；保留强认证 |
| 已挂失 | 挂失 | 明确无需重复挂失，不生成写步骤 |
| 正常 | 解挂 | 明确无需解挂，付款受限原因须另查 |
| 未知/其他状态 | 两者 | 先核验状态，不生成写步骤 |
| 缺ID/重复ID/未知操作/查询失败 | 任意 | 明确缺失或歧义，提供澄清、复核或人工选项 |

空列表只表示本次查询范围无卡；查询失败不能说用户没有卡。多卡时所选目标的状态独立分析，不被其他卡的未知状态污染。保留原始 facts/evidence，不改动资金事实、不使用系统时间、不查询外部系统。

## 与其他 Agent 及平台的关系

- 主 Agent 准备可信身份与具体卡片实体，解释候选步骤；Supervisor 校验证据和工具参数。当前两域只在已有工具结果上分析，不能替代 Planner 或 PolicyEngine。
- 支付/财务健康域：挂失后付款需重做支付预检；卡恢复正常不等于余额、限额、预算或其他条件已满足。复用现有支付链，不构造跨域执行DAG。
- 订阅域：隐藏卡、挂失、注销、取消扣费授权分别处理。本域不声称挂失已取消订阅，也没有事实说明哪些订阅绑定该卡。
- 家庭域：用户自称家属不产生代办权；强认证由平台完成，不收集OTP或自行签发凭据。
- 反诈域：丢卡和卡状态异常仅作为业务情形，不自行认定诈骗、冻结其他账户或替代风险裁决。
