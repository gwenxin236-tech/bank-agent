# C4 家庭授权矩阵与本人认证边界

## 1. 交付范围与演示身份

本任务提供**离线、单进程服务的跨用户授权替身**，不连接真实银行账户、登录平台或短信供应商；不宣称通过生产身份认证、授权或容灾验收。前端沿用已有界面，本次家庭专项演示使用 HTTP 接口和自动化测试。

`config/guardianship.json` 是已取得本人同意的**演示夹具**，不是客户端可提交的授权书。首次启动将关系写入 SQLite；重启用 `INSERT OR IGNORE`，不会把已撤销、已过期或调低的授权恢复为配置初值。没有公开创建、修改、撤销授权的 HTTP 接口。`GuardianshipStore.update` 仅供受信测试/管理适配器使用。

| 身份 | user_id | 绑定设备 | 独立开仓余额（分） | 演示会话 |
|---|---|---|---:|---|
| 父亲 | family-father-demo | father-device | 2000000 | demo-father-session |
| 女儿 | family-daughter-demo | daughter-device | 300000 | demo-daughter-session |
| 母亲 | family-mother-demo | mother-device | 1500000 | demo-mother-session |

**这些会话字符串公开且固定，不是真实登录凭据。验证码仍为演示值 `123456`。** 它们用于验证“登录身份由适配器提供，不能通过请求体改写”的边界，不能防止知道父亲演示会话的人模拟父亲。生产必须整体替换会话和强认证适配器。

女儿对父亲默认 `limited_transfer`、每日 100000 分；对母亲默认 `read_only`。授权模型字段为 `grant_id / guardian_id / subject_id / authorization_type / daily_limit_cents / valid_from / expires_at / revoked`，有效区间 `[valid_from, expires_at)`。

## 2. 确定性授权矩阵

`PolicyEngine.classify` 将 `GuardianshipStore.evaluate` 的确定性授权结果和 C2 风险分合并；模型不能批准权限。配置中小额单笔上限为 **100000 分（含 1000 元边界）**。所有金额、余额和额度均为整数分。

| 操作 | 只读查询授权 | 限额转账授权 | 全额授权 `full` |
|---|---|---|---|
| 查被守护人余额、流水、账单 | 有效关系内允许 | 允许 | 允许 |
| 小额转账代办（不超过单笔上限及每日剩余额度） | 拒绝 | **本人强认证后**允许 | **本人强认证后**允许 |
| 超过单笔上限的大额转账代办 | 拒绝 | 拒绝 | 拒绝 |
| 修改密码、挂失、解挂代办 | 拒绝 | 拒绝 | 拒绝 |
| 协助发起大额/密码/卡片业务 `assist` | 可以发起，由本人认证并最终确认 | 同左 | 同左 |
| 关系未生效、过期、撤销、无关系 | 拒绝 | 拒绝 | 拒绝 |

`full` 表示覆盖本演示支持的可代办业务集合，**不是无限额度、管理员身份或本人认证豁免**；仍受每日额度、小额单笔上限及硬禁止矩阵约束。`assist` 不代表执行授权：只读守护人也可帮助填写申请，但不能完成认证或最终提交，不占代办额度。

其它尚未适配账户隔离的业务（例如旧零花钱、生日联动、理财、订阅）对家庭夹具账户关闭，不落回共享演示账户。密码、挂失、解挂在本人认证后仅返回 `HANDOFF_REQUIRED` 的未完成结果，明确要求官方人工办理，**不伪称已经改密、挂失或解挂**。

### 两条执行路径

- **小额代办 `delegate`**：女儿发起 → 女儿或父亲请求认证挑战 → **父亲绑定设备/会话通过认证** → 女儿或父亲确认执行 → 扣父亲余额，同时占用女儿对父亲的每日代办额度。
- **只能本人执行的 `assist`**：女儿协助发起 → 女儿确认被拒并写 `authz.denied` → 父亲请求挑战、强认证、最终确认 → 本人转账或进入人工办理。大额转账不扣代办额度，仍受本人日限额、C2 风控及 C5 冻结约束。

内部 `AgentRuntime` 的 actor/device 参数属于**可信适配器上下文**，不是对公网开放的身份认证 API。`FamilyAccess` 从受信会话导出身份；原有 `/api/chat`、`confirm`、`verify`、`cancel` 也校验家庭会话，不能通过旧路由、伪造 `user_id` 或省略身份绕过。

## 3. C1/C3/C5/C8 一致性

- `plan.actor_id` 始终是资金所有者；父亲任务绑定父亲设备。真实发起人、授权关系、模式存在服务端写入的 `entities._family`。模型返回的同名字段被删除，不接受模型自授权限。
- `_family` 一并进入计划/认证摘要，继承 C3 的金额、收款人、任务、设备、有效期及一次性消费检查。女儿即使知道正确演示验证码也不能以女儿身份认证父亲任务。
- 规划时、确认时、每个工具调用时、扣款前均复核授权。`classify_tool` 对家庭账户另做意图—工具白名单匹配，防止把已注册但无关的副作用工具塞入查询任务。
- 家庭关系撤销与最后执行门禁共用银行锁，额度预占使用独立 SQLite 连接的 `BEGIN IMMEDIATE` 和唯一 `task_id`。同服务并发两笔各 600 元、日额度 1000 元，最多一笔成功。
- `guardianship_usage` 状态为 `reserved / consumed / released`。先持久化预占，再调用一次核心工具；确定成功占用，确定失败释放，`processing` 保留。状态查询可核对并更新**本地额度元数据**，绝不重发转账或扣款。
- 崩溃发生在“已预占、核心结果未知”之间时保守保留额度；如果没有可查询核心交易，须人工核对，不自动释放或重发。冲正返账户资金，但**不返当日代办额度**，避免循环使用额度。
- 业务日使用 UTC+8；额度归属于提交/预占当天。跨日重置每日额度，不迁移历史交易归属日。
- 家庭账户余额由独立开仓值减去其核心已扣款流水计算，重启不再扣一次；余额、流水、账单不会读到旧 `demo-user` 的数据。该做法是核心账本替身，不是复式总账实现。
- 审计链中的 `user_id` 归资金所有者，`authz.denied` 另记守护人和原因；`policy.decided` 保留授权结论及风险依据，C3 事件记录本人认证，C1 查询记录最终状态。授权和额度均有 SQLite 持久证据。
- C8 任务检查点保存含 `_family` 的计划；重启不自动跨过确认节点。恢复后的过期凭证必须重新认证，完成任务不能重复执行。

## 4. C2 通知联动

`NotificationBus` 支持一个被守护人的多个有效守护人；保留旧单目标回调兼容。发生交易暂缓、反诈阻断、认证失败、设备风险时，事件归被守护人，App/SMS 通道不变，守护通道向有效守护人本地入队。发布及未审计回执恢复时重查关系；旧订阅失效时标为 `SUPPRESSED`。

`LOCAL_QUEUED` 仅代表本地模拟入队，**不代表真实推送、短信已经送达**。新家庭通知查询只返回登录守护人的守护通道记录；过期、撤销后不能继续读取该关系的历史通知。既有账户通知、交易状态、审计详情不向匿名请求或其它家庭用户泄露；本人可用可信会话查询。演示会话无权自行解冻家庭账户。

## 5. HTTP 接口与演示步骤

所有家庭接口使用 `Authorization: Bearer <演示会话>`。若请求体同时提供 `user_id/device_id`，必须与会话一致。不能提交授权类型、额度来提升权限。

| 接口 | 用途 |
|---|---|
| `POST /api/v1/family/chat` | `message / subject_id / mode`；mode 默认 delegate，支持 assist |
| `GET /api/v1/family/grants` | 当前登录守护人的关系、有效性、每日剩余额度，不返回会话字段 |
| `GET /api/v1/family/notifications` | 当前登录守护人的有效关系通知收件箱 |
| `POST /api/confirm` | 原有 plan_id/action_token/credential_id；新增家庭身份校验 |
| `POST /api/verify` | 原有 plan_id/action_token/credential_id/code；父亲任务必须父亲会话 |
| `POST /api/cancel` | 校验任务发起守护人或被守护人身份，不产生扣款 |
| `POST /api/v1/tasks/status` | 沿用 C8；账户本人会话及任务 token/绑定设备查询 |

先执行 `./run.sh`，以下命令均访问本机演示服务：

```sh
# 女儿查父亲余额
curl -s http://127.0.0.1:8090/api/v1/family/chat \
  -H 'Authorization: Bearer demo-daughter-session' -H 'Content-Type: application/json' \
  -d '{"subject_id":"family-father-demo","message":"查询余额"}'

# 创建 1000 元代办任务；记录响应 plan.plan_id 和 plan.consent_token
curl -s http://127.0.0.1:8090/api/v1/family/chat \
  -H 'Authorization: Bearer demo-daughter-session' -H 'Content-Type: application/json' \
  -d '{"subject_id":"family-father-demo","message":"给妈妈转 1000 元","mode":"delegate"}'

# 使用响应中的值替换变量，不要使用其它任务的 token
PLAN='<plan_id>'
TOKEN='<consent_token>'
curl -s http://127.0.0.1:8090/api/confirm \
  -H 'Authorization: Bearer demo-daughter-session' -H 'Content-Type: application/json' \
  -d "{\"plan_id\":\"$PLAN\",\"action_token\":\"$TOKEN\"}"

# 记录上一步 auth_challenge.credential_id；改用父亲会话认证
CREDENTIAL='<credential_id>'
curl -s http://127.0.0.1:8090/api/verify \
  -H 'Authorization: Bearer demo-father-session' -H 'Content-Type: application/json' \
  -d "{\"plan_id\":\"$PLAN\",\"action_token\":\"$TOKEN\",\"credential_id\":\"$CREDENTIAL\",\"code\":\"123456\"}"

# 女儿代办提交；同一凭证重放会被拒绝
curl -s http://127.0.0.1:8090/api/confirm \
  -H 'Authorization: Bearer demo-daughter-session' -H 'Content-Type: application/json' \
  -d "{\"plan_id\":\"$PLAN\",\"action_token\":\"$TOKEN\",\"credential_id\":\"$CREDENTIAL\"}"
curl -s http://127.0.0.1:8090/api/v1/family/grants \
  -H 'Authorization: Bearer demo-daughter-session'
```

5000 元 `delegate` 直接得到 `AUTHZ_DENIED` 和可查的 `trace_id`。改为 `assist` 重新发起，再**全部使用父亲会话**完成 confirm → verify → confirm，可完成本人转账；旧失败任务不能改模式复用。

请使用独立临时数据库重放验收，避免已有余额、日额度、连续交易风险特征影响现场预期。风险分仍可优先暂缓，不因家庭授权而绕过反诈。

## 7. 生产替换点与上线门禁

| 演示实现 | 必须替换/补齐 |
|---|---|
| 固定会话、绑定设备、固定 OTP | 可信 IAM/实名登录、设备证明、多因素强认证；严禁客户端自报 actor，严禁公开演示会话和 OTP |
| JSON 预授权、受信 update | 本人授权书、身份/关系核验、审批版本、可撤销且可审计的授权服务；权限不交给模型 |
| 单服务锁、SQLite 每日额度预占 | 跨实例一致的授权版本/条件扣额度事务、核心预占/解冻、冲正对账、事务 outbox；不能把当前局部锁当分布式保障 |
| 开仓值减持久交易流水 | 真正隔离的账户核心、复式账务与账本核对、业务日历、核心最终态查询与统一幂等协议 |
| 人工办理提示 | 银行实名人工工作台/卡片与密码办理流程；本人认证及授权不能被助办人继承 |
| 本地通知模拟及哈希链 | C2 供应商 Adapter、可靠消息/回执与订阅同意、C5 WORM/SIEM、分权运维解冻 |
| C8 单机检查点 | 生产密钥管理、共享持久任务库、备份灾备及压力/故障验收 |

旧 `demo-user` 的开放演示接口并未改造成生产登录体系；本轮只将配置中的家庭账户纳入严格入口与工具隔离。部署仍须保持离线演示边界。生产上线必须关闭演示身份、演示解冻/重置及开放演示查询，并统一部署可信认证网关和运维授权体系。
