# T11 领域注册与六域适配

## 本批目标与限制

落实内部《领域Agent开发手册》的六域接口、自注册、只读事实与建议目标（L3）。这不是官方“至少三类领域”要求。本批复用既有风险特征、账本、守护授权、订阅与卡管工具，不改业务权限、不新增第三方依赖、不执行领域建议。

## 注册与成员入口

`app/domain_agent_registry.py` 导出 `DOMAIN_AGENT_REGISTRY`；加载器只导入 `agents.<六个合法域>_agent`，在临时表完成全部注册、校验后一次发布只读映射。模块缺失、漏注册、重复、越域、外部模块类或导入异常均拒绝发布，不污染原注册表。此处“六域齐全”是本项目启动约束，不是赛题要求。

每个模块定义如下函数，不改银行工具注册表、不修改中央注册字典：

```python
def register(registry):
    registry.register(YourDomainAgentClass)
```

注册类必须属于对应 `agents.<domain>_agent` 模块并具有 domain/analyze/propose；支付注册类继承 T10 TransactionAgent，其余继承只读 SnapshotAgent 共用快照绑定逻辑。调用示例：

```python
from domain_agent_registry import DOMAIN_AGENT_REGISTRY
agent = DOMAIN_AGENT_REGISTRY.create(domain, trusted_snapshot)
finding = agent.analyze(ctx)
proposal = agent.propose(ctx, finding)
```

每次创建独立实例，注册器不缓存 Context/客户事实。域名来自六个固定本地模块，不接受用户提交的模块路径。与既有 `features/*` 示例工具注册器是两个层次；注册 Agent 不授予工具权限。

## 六域能力与真实接入位置

| 域 | 实现与事实源 | 当前接入 |
|---|---|---|
| payment | `agents/payment_agent.py` 继承 T10；既有 payment preflight 六项检查 | 转账规划中的支付分析，保持原确认/MFA/执行 |
| antifraud | `agents/antifraud_agent.py`；已有 PolicyEngine/risk_controls 特征或 detect_fraud_signals 工具结果 | 原策略记录后、反诈工具返回后；不重新评分、不自行冻结或设置冷静期 |
| finance_health | `agents/finance_health_agent.py`；ledger_views 已生成的消费、资金流、资金状态、覆盖范围 | financial_health_report 工具返回后；不再查银行，不把单账户当完整家庭资产 |
| family | `agents/family_agent.py`；GuardianshipStore 既有授权记录或旧家庭成员工具结果 | 有效范围内的家庭策略记录后、家庭工具返回后；只报告额度/有效期/撤销状态，不调用授权矩阵替代 PolicyEngine |
| subscription | `agents/subscription_agent.py`；list_subscriptions 已返回的交易/代扣/服务三层数据 | 仅原工具已经执行后；不会为了 Agent 在黄色确认前新增查询 |
| card | `agents/card_agent.py`；list_cards/verify_card_status 已返回的状态 | 原红色强验证后卡工具返回；只建议挂失/解挂与核验，不改密码、不直接改卡状态 |

注册完成不等于每次请求都跑六域。T11 根据已有业务节点观察对应事实，尚无 Supervisor 的多域路由、事实冲突合并或建议驱动计划；仍用原 Planner、PolicyEngine 和工具执行链。所有分析事件标记 ADVISORY_ONLY，建议没有传给执行器。

## 快照、权限与失败语义

`app/domain_snapshots.py` 不接受 Bank/Runtime/DB/工具回调，不执行查询：

- `policy_snapshot(ctx, decision)` 只投影既有 risk_score/risk_factors/AML/次数字段；不向 Agent 转发 authz_allowed、risk_level、defer。未运行风险计算时注明 PolicyEngine 默认特征来源，不冒充已运行 assess_transfer_risk。
- `tool_snapshot(ctx, domain, result)` 校验工具属于该域，投影所需事实。订阅保留历史扣款、未来代扣、服务状态、退款状态，不把未知退款记为到账；卡片仅投影 ID/名称/状态，不传完整卡号。
- `family_snapshot(ctx, grant, now)` 校验 guardian/subject 与 Context 相符，报告 grant_type、daily_limit_cents、有效区间、revoked 与捕获时有效性；没有、过期或撤销的授权不产生写建议。
- 旧财务健康、订阅、卡片、家庭成员工具仍包含 demo-user 全局数据，因此本批快照拒绝把它们标成其他 actor/subject 的资料。未接入真实多租户数据源，不声称修复了所有旧工具的数据隔离边界。
- 深复制与递归冻结沿用 T10；整个 Context 摘要绑定 trace/session/actor/subject/device/channel/输入。失败或缺失来源标为 unknown/missing，不填零当成功。来源引用来自已知平台模块；不构成签名凭证，不允许把 HTTP/LLM 字典冒充 ToolResult。

各 Agent 的 analyze/propose 只读取快照，无核心、审计、通知或数据库句柄。缺失订阅 ID 时只列候选，未选择/不可终止项不建议取消；卡 ID/操作/状态不明、已经挂失时不重复建议挂失。原生 Python 注册器是受信代码协作边界，不是不可信插件沙箱。

后置分析异常只记录 `domain.<域>.unavailable`，不重查、不重提原银行工具、不把已经返回的真实工具结果改写成另一结果。T10 支付规划分析异常仍按原设计阻止本次计划进入待执行队列。若审计存储本身故障，继续走原平台恢复/失败关闭机制，不保证还能返回正常回执。

`domain.<域>.analyzed` 审计保存 mode、Context 摘要、事实数量、来源引用、缺失项、风险信号与建议工具名称；不存原话、完整事实副本、token 或 OTP。人工结论仍只走 T09 本地接管流程。
