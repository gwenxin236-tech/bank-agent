# T10 领域契约与支付样板（Step 1）

## 对应要求与范围

本批落实《领域Agent开发手册》§3 的内部接口、§1 支付样板以及“Agent 不执行副作用”的边界，属于 L3 项目自定设计。多领域 Agent 和六领域划分不是官方硬性要求。本批复用既有 `preflight.build_payment_preflight`、PolicyEngine、确认/MFA、执行工具与审计，未新增依赖或改写安全执行平面。

## 交付接口

| 接口 | 用法与约束 |
|---|---|
| DomainContext | trace/session/actor/subject/device/channel/user_input/entities；由可信平台构造，actor 与 subject 分离；用户原话只作数据 |
| DomainFinding | domain/facts/missing_fields/risk_signals/recommendations/evidence；事实必须有来源引用，不独立授予权限 |
| DomainProposal | suggested_steps/required_confirmations/required_auth/user_options/production_replacement；建议不是可执行授权 |
| DomainAgent | analyze(ctx)、propose(ctx, finding)，只读 Protocol |
| AgentMessage | `from_context(ctx, sender, recipient, payload)`；仅六领域与 supervisor 内部端点，Finding 的域须匹配发送者；关联 trace/session/context 摘要 |
| AgentHandoff | `from_context(ctx, sender, recipient, reason, required_fields)`；固定原因 missing_information/domain_boundary/unknown_result；不携带原话、token、OTP，不自动创建或领取真人工单 |

前三个数据类和 Protocol 在 `app/domain_agent_contract.py`；信封、内部移交、PaymentSnapshot 与 TransactionAgent 在 `app/transaction_agent.py`。这是当前负责人提供的共用接口，成员不要重复定义。

构造时接收普通字典/列表，内部递归冻结为只读 Mapping/tuple，`.to_dict()` 返回可独立修改、可 JSON 序列化的副本。禁止 float 和非 JSON 对象；`*_cents` 只能是 int（不能是 bool/字符串），未知允许 null。按字段限制结构深度、条目数量、字符串和序列长度，拒绝未知顶层构造参数。

契约递归拒绝 allow/authorized/approved/authz/permission、policy_override、skip_auth、action_token 等授权/凭据字段，也识别大小写、驼峰与连字符常见变体；建议步骤只允许 tool/params/可选 title，不能夹带 retry 参数。此校验不是识别任意自然语言越权的安全模型，字符串仍是不可信内容；仅靠 evidence 字符串不能证明来源真实。

## 支付样板与来源

平台先生成现有预检，再创建快照：

```python
from domain_agent_contract import DomainContext
from transaction_agent import PaymentSnapshot, TransactionAgent, AgentMessage

# ctx 只能由可信身份入口构造；report 是平台已生成的 PreflightReport。
agent = TransactionAgent(PaymentSnapshot.from_preflight(ctx, report))
finding = agent.analyze(ctx)
proposal = agent.propose(ctx, finding)
message = AgentMessage.from_context(ctx, 'payment', 'supervisor', finding)
payload = message.to_dict()  # 数据，不交给工具执行器直接执行
```

快照绑定整个 Context 的摘要，并检查 report.actor_id=ctx.subject_id、金额与收款人一致；不能跨 trace、会话、actor、subject、设备、渠道或输入复用。深复制冻结后，调用方不能通过改原字典污染证据。以上是受信 Python 集成的结构/绑定校验，不是签名证明，也不是不可信 Python 插件的沙箱。

六项事实完整复用预检：available_funds、daily_limit、beneficiary、card_status、authentication、budget。每项携带 `preflight.py:build_payment_preflight#维度` 来源及预检原始 evidence。事实分为底层只读查询、平台策略配置、请求回显和预检派生计算：请求金额不是银行已完成交易，预算和预计累计为可追溯计算，不冒充银行已扣款数据。样板不接收 Runtime/Bank/DB/工具回调，也不发模型请求或写审计。

样板的金额/收款人缺失、新收款人未核验、未知或不满足的事实均不产生写工具建议；预算缺口只给 adjust_amount/adjust_budget/defer/human_handoff 四项选择，不建议借款、不自动扣款。条件齐全时只建议现有 resolve_beneficiary/check_transfer_constraints/create_transfer 三步，执行仍需平台重新验证。确认和 strong_auth 提示来自预检中的现有策略要求，不在样板里另设金额阈值。

## 当前主链接入

`AgentRuntime._chat` 在原有注入拦截、策略裁决和预检之后，以当前可信身份和预检创建支付样板，生成 Finding/Proposal，并记录 `domain.payment.analyzed`、mode=ADVISORY_ONLY。审计仅保存摘要、事实数量、来源引用、缺失/风险项和建议工具名称，不保存原话或 token。支付建议没有传给执行器，也不覆盖原 AgentPlan、风险等级、确认或 MFA。

分析异常会记录固定错误并阻止本次计划入待执行队列，不回显异常细节，不回退到未经分析的可执行计划。未知/不完整业务仍先走原澄清路径；拒绝或注入请求不会为了分析而额外读取账户。
