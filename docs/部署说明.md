## 渠道无关网关接口

当前为 Web + 本地终端演示，没有真实第三方 IM：

- `POST /api/chat`：可接收 `channel`、`conversation_id` 和 `message`；主要业务入口要求演示 Bearer 会话，user_id/device_id 不能通过请求体冒充；

## Docker 隔离验收

先启动 Docker Desktop 的 Linux 引擎，在项目根目录执行：

```sh
python scripts/docker_qa.py
```

入口读取并校验现有 Compose 配置，再生成仅包含演示服务的独立验收配置。
它使用临时数据目录、独立项目名和随机的 `127.0.0.1` 端口，不挂载现有 `data/`。
验收项目包括镜像非 root 运行、构建内容边界、健康检查、前端访问、模拟转账，
以及强制重建容器后余额、交易和审计是否保留、旧确认是否被拒绝。
完成或失败后均尝试清理本批容器和网络；本次构建的镜像保留用于复核。
结果与原始命令输出保存至 `data/verification/t04-*/report.json`。

首次构建需要从 Docker Hub 获取 `python:3.12-slim`；应用的离线演示运行不需要外部模型。
若下载阶段出现 `registry-1.docker.io` 或 `auth.docker.io` 的 EOF/TLS 错误，
镜像构建尚未完成，不能将后续健康和持久化项目记为通过。恢复 Docker 的仓库连接后重跑即可。
`.dockerignore` 排除本地数据库、验收日志、浏览器测试工具、内部过程资料和提交材料。
