# 开发者指南

## 接入真实大模型

不要把 API Key、系统提示词或工具凭证放进客户端。建议采用以下模式：

```text
客户端消息
  -> Agent Gateway
  -> LLM Router（结构化 JSON Schema 输出）
  -> Schema Validator
  -> Policy Service
  -> Tool Gateway
```

大模型输出只允许产生 `intent/entities/missing_fields/explanation`，不允许产生“已转账”这类事实性结果，也不允许直接决定 `allow_tool=true`。

## 接入银行工具

实现一个 `BankAdapter`，将内部 API 封装为类型安全工具：

```python
class BankAdapter:
    def resolve_beneficiary(self, ref: str) -> ToolResult: ...
    def get_balance(self, account_id: str) -> ToolResult: ...
    def create_transfer(self, request: TransferRequest) -> ToolResult: ...
    def get_transfer_status(self, transaction_id: str) -> ToolResult: ...
```

转账必须：

- 服务端生成幂等键；
- 在扣款前再次读取账户状态和额度；
- 对超时采用“查询状态”而不是盲目重试；
- 对失败/未知状态进入人工或对账队列；
- 将核心流水号回填到审计。

## 接入多模态

- ASR：输出文本和置信度；低置信度要求用户复述。
- OCR：只提取必要字段，银行卡号和身份证号默认遮罩。
- Vision：用于读账单或截图，不允许直接识别并执行转账。
- 语音播报：红色操作不通过语音单通道确认，必须在可信 UI 内完成。

## 版本与发布

策略配置、Prompt 模板、工具 Schema、模型路由和前端必须分别版本化。每一个生产操作的审计事件需要记录版本，以便在争议中重建当时系统行为。
