## 1 封面

**澜银行 AI 智能体**：把复杂银行业务，说给我听。

一句话：用自然语言完成银行服务，但把最终控制权交给策略、认证与审计。

## 2 痛点

- 手机银行操作路径深，用户知道“想做什么”但不知道“去哪里做”。
- 传统客服能回答，不能安全地完成业务。
- 金融 Agent 的关键不是会说，而是可控、可追责、可恢复。

## 3 产品体验

本批实际视频使用独立临时 Mock 库，演示：

1. 查余额：绿色自动完成。
2. 有限上下文：先“给妈妈转账”，再补“200元”，不等于授权。
3. 200 元转账：核对实际计划、点击确认、显示模拟工具结果。
4. 2000 元转账：强验证后再确认。
5. 订阅查询黄色确认、规则注入拦截与审计回放。
6. 本地接管排队及进度查询，不声称接通真人。

## 4 六域协作

- payment、antifraud、finance_health、family、subscription、card 六个独立注册域，依据 `app/domain_agent_registry.py`。
- 模块只分析平台快照并给建议，不是六个自主联网模型；Supervisor 固定路由、比对来源、保留冲突。
- 六域是项目自定目标，不把多领域或“至少三类”说成官方硬要求。原稿的外部案例/标准借鉴不作为本批已验证成果。

## 5 系统架构

展示输入/身份 → 解析/原规划 → 证据/权限 → 原确认/演示认证 → DAG/固定工具 → Mock/审计的职责链。Supervisor 当前计划核对限原转账模板；其他域按既有授权来源分析。绿色按策略自动执行，不等待确认。真实银行与生产身份不是已接入模块。

## 6 Agent 核心算法

默认规则意图识别、有限上下文、固定模板与受限模型协议；持久 DAG 拒环、checkpoint、重启恢复与节点边界暂停。回退仅做已声明补偿，未知结果不重发、不凭空退款。事实来自 Mock 工具，不称“真实银行结果”。详见 `docs/架构与技术方案.md` §9、`tests/test_dag_integration.py`。

## 7 三色权限

用三列解释：

- 绿色：查余额、流水、分析，自动执行。
- 黄色：普通转账、订阅查询与取消，原计划明确确认；订阅查询虽只读仍为黄色。
- 红色：超过日累计边界的转账、既有挂失/解挂等操作，固定 OTP 演示认证后再次确认；不把所有策略意图当作完整业务实现。

## 8 安全闭环

规则注入拒绝、服务端策略、固定工具、幂等、SQLite 哈希链、共享 runtime 熔断及本地工单。有限语料不是所有攻击保证；哈希链不是 WORM；工单结单不改交易状态。沙箱是 T07 历史受限计算专项，最新镜像未验收，本片不冒充已录制最新沙箱。
