# 适老化产品与安全方案

## 一 目标和边界

本方案把银行 AI 智能体设计成“长辈也能看懂、重要操作不容易点错”的银行服务入口。适老化不是把字放大这么简单，还要减少专业词、降低一次需要记住的信息量、在有资金影响的操作前重复说明，并且保留人工帮助出口。

当前实现属于可运行原型。它完成了界面和交互基线，不代表已经完成银行生产系统需要的身份、风控、合规、无障碍测评和监管审批。

## 二 适老化设计原则

### 1 用日常说法代替系统词

| 系统词 | 长辈看到的说法 |
|---|---|
| Agent | 银行小助手 |
| 风险等级 | 安全提示 |
| 绿色 自动执行 | 可以直接办理 |
| 黄色 需要确认 | 请你确认后办理 |
| 红色 强验证 | 需要再次验证 |
| 计划 | 这次要做的事 |
| 工具调用 | 系统正在办理 |
| 额度校验 | 看看今天还能不能转这么多 |
| 订阅 | 会自动扣钱的服务 |
| 交易号 | 办理编号 |
| 取消操作 | 先不办理 |

内部仍可使用 JSON、枚举和工具名，但这些字段不能直接作为普通用户的文案。

### 2 一次只让用户做一个决定

对于转账，页面按以下顺序呈现：

1. 先告诉用户要转给谁；
2. 再告诉用户多少钱；
3. 再告诉用户备注和账户影响；
4. 用一句话重复“确认后会发生什么”；
5. 只提供“确认办理”和“先不办理”两个主操作；
6. 大额或异常操作再进入短信、刷脸或其他强认证。

### 3 不让语音直接产生资金副作用

浏览器语音输入只负责把说话内容填入输入框。用户仍要检查识别结果并主动发送；转账、取消自动扣费、挂失、改密等操作仍必须经过文字确认和强认证流程。生产版还要考虑录音授权、音频留存、声纹误识别和家庭成员代操作风险。

### 4 永远保留人工帮助

长辈可能会说“我不明白”“这是不是扣钱”“帮我找客服”。系统应给出人工客服入口。进入人工接管后，模型不得继续调用有副作用的工具，客服操作也必须进入同一套授权和审计链路。

## 三 当前前端能力

- 默认开启大字易懂版，可切换普通版；
- 一级按钮使用“查余额、看消费、转一笔钱、看自动扣费”；
- 计划卡片改为“这次要做的事”；
- 风险文案改为可以直接办理、请你确认后办理、需要再次验证；
- 重要操作显示收款人、金额、备注和步骤；
- 语音输入入口；
- 高对比度焦点样式；
- 较大的点击区域；
- 手机屏幕响应式布局；
- 异常情况使用“没有办理、没有扣钱、请联系人工”等结果文案。

## 四 适老化验收用例

| 用例 | 通过标准 |
|---|---|
| 查询余额 | 用户不看 JSON、不懂内部术语也能知道余额结果 |
| 转账 200 元 | 用户能说出收款人、金额、备注和确认按钮含义 |
| 转账 2000 元 | 页面明确说明需要再次验证，不把验证码当作普通提示隐藏 |
| 识别失败 | 页面显示“没有听清”，不会自动发送或执行 |
| 误点确认 | 取消按钮与确认按钮均清晰可见，取消不产生业务副作用 |
| 看不懂计划 | 用户询问“这是什么意思”时，可以由 Agent 用自然语言解释 |
| 家人代办 | 生产版必须通过受托授权、设备绑定和可撤销授权，不以知道密码作为授权依据 |

## 五 生产版还需要做的事

- 由无障碍和适老化专家进行可用性测试；
- 覆盖大字体、读屏、色觉差异、低带宽和旧设备；
- 对短信、刷脸、语音识别和生物特征做安全与隐私评估；
- 设置长辈专属的异常转人工策略；
- 对疑似诈骗、诱导转账、远程控制和异常收款人增加风险提示；
- 为家属协助、监护和授权代理建立合规流程；
- 将适老化文案纳入产品发布前的回归测试，不允许后续模型自由生成难懂术语。
