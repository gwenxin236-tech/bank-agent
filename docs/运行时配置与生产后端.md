# 运行时配置与生产后端

## 目的

项目默认是标准库 Demo，启动不依赖 Redis、PostgreSQL 或任何真实银行系统。为了避免“配置了生产变量但实际仍然使用内存/SQLite”的假生产状态，项目增加了运行时前置检查和显式后端构造器。

## 本地演示

```bash
python scripts/preflight.py
python scripts/smoke_test.py
```

演示环境的 `/api/preflight` 会报告 `READY_FOR_CONFIGURED_RUNTIME`，但业务 readiness 仍会明确显示 `NOT_READY_FOR_PRODUCTION`。这两个状态含义不同：前者表示本地服务配置可以启动，后者表示尚未具备银行生产资格。

## 生产后端实现

`app/production_backends.py` 提供以下可选实现：

- `RedisTaskStore`：任务状态，带 TTL；
- `RedisMessageQueue`：任务队列和死信队列；
- `PostgresTaskStore`：任务状态持久化；
- `PostgresAppendOnlyAuditSink`：追加式审计记录和哈希链。

只有显式设置 `TASK_STORE_BACKEND` 或 `AUDIT_BACKEND` 并安装 `requirements-production.txt` 后，才会构造这些后端；缺少连接串或客户端依赖会直接报错，禁止静默回退到内存。

这些代码仍然不是银行生产联调的替代品。生产必须继续完成 TLS/mTLS、服务身份、连接池、权限隔离、容量和故障演练，并把审计数据送入 WORM、SIEM 和 KMS/HSM 体系。

## 前置检查

- `GET /api/preflight`：返回无副作用的配置检查；
- `GET /health/live`：进程存活检查；
- `GET /health/ready`：配置就绪检查；生产阻断项存在时返回 HTTP 503；
- `scripts/preflight.py --probe-network`：可选短连接探测，不发送业务数据。

生产环境至少应设置：

```dotenv
APP_ENV=production
ALLOW_DEMO_CORE=false
TASK_STORE_BACKEND=redis
AUDIT_BACKEND=postgres-worm
REDIS_URL=rediss://...
POSTGRES_DSN=postgresql://...
KMS_KEY_ALIAS=真实KMS密钥别名
SIEM_ENDPOINT=https://真实SIEM入口
```

真实密钥、密码、证书和生产地址不能提交到 GitHub，也不能写入 `.env.example`。
