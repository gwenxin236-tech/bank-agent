# E7-A 卡片写操作边界

## 1. 演示能力

本项目新增一条可验证的卡片写操作链路：

```text
“我的卡丢了，帮我挂失”
  → 生成红色操作计划
  → 用户确认
  → 强认证（本地演示验证码 123456）
  → MockBankCore 卡状态 normal/正常 → reported_loss/挂失
  → 只读核验最终状态
  → 审计 card.loss.completed + card.status.verified
```

解挂使用同一条红色强认证链路，只有认证通过后才允许把状态恢复为“正常”。同一计划的副作用使用幂等键；重复调用返回原结果，不重复产生卡片状态变化。挂失后的支付预检读取同一份 MockBankCore 卡状态，卡状态维度变为 `missing`，不会因为预检而扣款。

## 2. 诚实边界

- 当前写操作只发生在离线 `MockBankCore`，是可现场验证的工程演示，不是真实银行卡管操作。
- `CardManagementAdapter` 是生产替换点；生产实现需要接入真实卡管/渠道服务，并完成强认证、状态核验、并发一致性、对账、超时语义、权限审计和灾备验证。
- `/api/readiness` 对“真实卡片写操作”保持 `blocked`，不会把 Mock 成功宣称为生产可用。
- Demo OTP `123456` 仅用于离线验收，不能作为生产认证方案。
- 卡号只在必要展示中保留末四位；审计不记录完整卡号或验证码。

## 3. 验收路径

1. 输入“我的卡丢了，帮我挂失”，确认计划显示红色并要求强验证。
2. 在本地演示输入验证码 `123456`，再次确认。
3. 观察回复使用工具返回的最终状态，并在卡片查询中看到“已挂失”。
4. 再发起转账预检，卡状态维度应为 `missing`，且余额不变。
5. 输入“帮我解挂银行卡”，再次完成红色强验证，核验恢复到“正常”。
