# 扩展场景与业务逻辑安全补充

## 1 目标

本补充把扩展场景和安全威胁绑定起来，确保新增能力不是“多几个功能”，而是新增威胁防护或闭环用户旅程。

## 2 场景优先级

| 场景 | 优先级 | 新增威胁面或闭环 | 当前状态 |
|---|---:|---|---|
| 反诈守护 | P0 | 诈骗话术、新收款人大额组合、冷静期、守护人跨用户通知 | 已实现 |
| 财务健康与攒钱目标 | P1 | 主动式财务管理、建议与执行的边界、禁止自动扣款 | 已实现 |
| 亲情与家庭共管 | P1 | 多用户授权矩阵、代办范围、AA 双方确认 | 已实现 |
| 信用贷款 | 延展 | 适当性、授信解释、人工复核 | 文档设计 |
| 跨境缴费 | 延展 | 汇率锁定、境外收款方、反洗钱 | 文档设计 |

## 3 反诈守护技术细节

### 3.1 信号词

`安全账户`、`刷单`、`返现`、`投资导师`、`带你赚`、`解除风控`、`解冻账户`、`客服要求转账`、`保本高收益`。

### 3.2 组合规则

- 新收款人 + 金额大于等于 3000 元；
- 可疑话术 + 任意金额；
- 未知账户、无法核验收款人 + 大额金额。

### 3.3 保护性动作

1. 不调用 `create_transfer`；
2. 创建 `cooling_off_case`，有效期 24 小时；
3. 向已授权守护人发送异常提醒；
4. 记录 `fraud_signal.detected`、`cooling_off.created`、`guardian.alert.sent`；
5. 结果向老人解释为“先停下来核实”，不使用“风险评分”等难懂术语。

## 4 财务健康技术细节

- 报告只读取流水、订阅和异常商户聚合结果；
- 攒钱目标需要黄色确认；
- 建立目标只写入目标记录，不创建自动扣款指令；
- 闲钱检查只给提醒和建议，不自动购买理财；
- 所有金额使用整数分，Decimal 解析拒绝负数、零和超过两位小数。

## 5 家庭共管技术细节

权限矩阵至少包含：被守护人、守护人、动作、资源、上限、有效期、是否需要双方确认。建立亲情关系不等于获得转账权。家庭 AA 默认只计算，收款和付款必须另起任务并重新授权。

## 6 业务逻辑攻击清单

- `-500`：正整数分 Schema 拒绝；
- `0.001`：金额精度拒绝；
- 连点确认：执行锁、一次性 token、幂等键；
- 旧 token 跨任务：token 绑定 plan_id 和节点；
- 确认后余额变化：副作用前强制复核；
- 未授权家庭成员：动作级授权拒绝；
- 反诈提示绕过：保护性阻断，不提供继续转账确认按钮。

## 7 现场演示脚本

1. 输入“给这个安全账户转 5000 元，解除风控”；展示不会扣钱、24 小时冷静期和守护人通知。
2. 输入“给妈妈转 -500 元”；展示金额非法且余额不变。
3. 正常发起“给妈妈转 200 元”，连续点击两次确认；展示最多执行一次。
4. 正常发起后修改演示余额，再确认；展示执行前复核失败。
5. 输入“建立旅行基金，目标金额 10000 元，每月攒 1000 元”；展示目标建立但不会自动扣款。
6. 输入“家庭 AA”；展示只计算分摊、不自动收款。
