# C7 — 适老化守护模式与生产替换点

## 1. 实现范围

长辈模式是**展示偏好，不是年龄认证或授权开关**。默认开启，浏览器通过 `localStorage.elderMode` 保存偏好；存储不可用时当前页面仍能切换。模式不改变账户年龄画像、PolicyEngine 判定、认证条件、金额、收款人、工具结果及账务状态，也不会重新提交当前业务。

- 正文与主要操作文案至少 18px，按钮触达高度至少 56px，深色文字与高对比度按钮，键盘焦点明确；支持减少动画偏好。
- 采用单列办理视图，保留余额和四个常用入口；技术性安全演示、服务记录可主动展开，办理步骤收拢。金额、收款人、确认与认证控件不隐藏、不跳过。
- 普通与白话两套展示随响应返回；切换时同步更新已有助手消息及当前办理卡片，不重新请求转账。用户原文不改写。
- 反诈守护或转账暂缓时展示红色 34px 标题 **“请先不要转账”**、解释、银行官方客服查找方式及 **96110** 咨询提示。不凭空提供本演示银行的电话号码，不把暂缓或 processing 改写成转账成功。

## 2. 白话文案层

配置入口为 `config/plain_language.json`：

```json
{
  "version": "自行维护的配置版本",
  "terms": {
    "触发增强认证策略": "为了保护您的钱，请再确认一次",
    "风险复核": "银行需要再核对一下"
  }
}
```

`PlainLanguage` 每次 HTTP 展示时读取配置，运维修改后下一次请求生效；已在浏览器中的历史消息保留收到时的版本。规则最多 500 条，键长 2–160、值长 1–240，最长词优先且只替换一次，避免级联替换。金额数字、货币符号及百分号不能作为替换规则内容，收款人、成员、备注等事实优先保护。文件缺失或不合法时使用内建基础词条，响应 `presentation.plain_language_status` 为 `fallback`。

`present_plain_response` 只转换 `message`、`plan_view`、`result_view` 内白名单展示文本。原始 `plan`、`result`、工具参数、action_token、机器状态及审计保持不变；`presentation.standard/plain` 用于切换。聊天、确认、认证、取消及客服响应共用该层；请求只有 JSON 布尔值 `elder_mode: true` 才启用白话顶层展示，不保存全局用户模式。

**配置是受信运维输入，不是用户可提交内容。** 数字保护不等于语义证明：禁止配置把失败映射为成功、删去风险条件或引导非官方渠道。生产应审批、版本签名、灰度发布并提供回滚，覆盖事实状态和业务实体的回归语料。当前模式主要覆盖 Web 展示边界，其他渠道接入时应显式复用该层。

## 3. 一键人工客服与 C2 总线

新增本地接口：

```http
POST /api/v1/customer-service
Content-Type: application/json

{"request_id":"help_demo_once","user_id":"demo-user","device_id":"demo-device","elder_mode":true}
```

- `request_id` 必填；三个标识均只接受 1–128 位字母、数字、下划线、连字符。用户/设备默认演示身份。
- 写入 C2 `customer_service.requested` 事件，同时写入同名业务审计及总线自身 `notification.*` 审计，返回可查询的 `event_id/trace_id`。
- 成功状态为 `LOCAL_QUEUED`：**仅本地记录，尚未接通真人客服，也不代表短信/App 已真实送达**。总线异常返回 503，不暴露内部异常、不假报送达。
- 同一用户的同一 request_id 重复提交、服务重启后提交均复用事件；客户端会话内保存请求键、共享按钮忙状态，不做自动重试。按钮再次点击属于显式重试；刷新复用会话键。新浏览器会话可发起新请求。存储禁用时仅当前页面复用键。
- 默认 App/短信订阅支持新事件，旧 C2 的系统默认订阅会升级；自定义订阅保留其显式选择。家庭授权仅允许风险提醒，**客服事件不发送给守护人**，也不允许守护人订阅客服事件。
- 客服请求不扣款、不调用业务副作用工具；点击后保留反诈警示与当前办理卡片。

查询现有 C2 接口：

```http
GET /api/v1/notifications/events?user_id=demo-user&trace_id=<返回的trace_id>
GET /api/v1/notifications?user_id=demo-user&trace_id=<返回的trace_id>
GET /api/v1/audit/verify?trace_id=<返回的trace_id>
```

新内部证据 ID 使用与 C2 一致的非数字字母编码，保持原随机熵，避免随机数字串误触 C5 脱敏而破坏 ID 关联；未放宽任何敏感字段掩码规则，已有 ID 不迁移。

## 4. 离线现场演示与验证

1. 启动 `./run.sh`，默认看到长辈模式、人工客服按钮、增大的文字和按钮。
2. 关闭模式，输入“给妈妈转 5000 元”，点击确认；关闭认证弹窗，再开启模式，验证“强验证”变成“为了保护您的钱，请再确认一次”。不要输入验证码也能完成此展示，切换不提交业务。
3. 输入“给妈妈转 1000 元，高收益稳赚”，看到“请先不要转账”、官方客服及 96110 提示，没有转账确认按钮。
4. 点击警示区“请人工帮我核实”或顶部“一键人工客服”，看到“尚未接通真人客服”；通过查询接口验证事件、通知和审计。重复点击仍为同一事件。
5. 修改受信术语表，发起新查询观察文案；关闭模式并刷新验证偏好保存。

必跑标准库测试：

```sh
python3 -m unittest discover -s tests -v
```

`tests/test_c7_elder_mode.py` 包含配置扩展/无效配置、展示事实保护、聊天/确认/认证链路、请求隔离、反诈与交易状态、客服幂等/重启/审计/故障、订阅授权和前端契约测试。内部 ID 脱敏回归位于 `tests/test_core_transaction_state.py`，随基线修复交付。

另有一个**可选开发期**真实浏览器验收：有现成 Node.js、Playwright 与 Chromium 的机器可运行，无需新增 Python 或应用运行时依赖：

```sh
C7_NODE_BINARY=/absolute/path/to/node \
C7_PLAYWRIGHT_MODULE=/absolute/path/to/node_modules/playwright \
C7_SCREENSHOT_DIR=/tmp \
python3 -m unittest discover -s tests -p test_c7_elder_mode.py -v
```

该测试启动回环地址临时服务，验证桌面/390px 手机端、实际计算字号与按钮尺寸、切换无额外 POST、警示、客服事件与重复点击、网络故障、不横向溢出及浏览器异常。未提供开发工具环境变量时只跳过此项；其余测试使用标准库。浏览器截图可选写到指定已存在目录，不自动安装依赖、不访问外部服务。

## 5. 生产替换点与边界

| 当前离线实现 | 上线前替换/补充 |
| --- | --- |
| 演示 user_id/device_id 与公开本地查询 | 从可信认证会话取身份，接入 IAM/RBAC、CSRF/来源校验、本人数据范围限制及终端绑定；不得信任客户端自报身份 |
| C2 SQLite 本地事件与 LOCAL_QUEUED 通知模拟 | 接入持久事件总线、人工坐席/工单 Adapter、真实 App/短信渠道；区分已受理/已派单/已接通/已送达，依据真实回执展示 |
| 会话级客服幂等键 | 与真实工单关联，明确人工服务结束/新建工单生命周期、限流和超时查询；转账仍禁止自动重试 |
| 静态适老词表与警示 | 银行业务、安全和适老化团队审校，官方客服渠道配置受管控，文案变更须状态事实回归；96110 提示不替代银行处置与紧急报警 |
| 浏览器自动化与桌面/手机截图 | 邀请长辈进行可用性测试，补齐读屏、键盘导航、缩放、多终端和对比度专项验收；不宣称已经获得无障碍合规认证 |

本任务不接银行核心、不拨打电话、不发送真实短信、不建立真人客服连接。安全中心折叠只降低展示复杂度，不减少任何后端权限检查或审计。
