# E3 双口径账本与资金状态视图

## 1. 交付边界

E3 在现有 `MockBankCore` 上增加只读视图层，不改账务写入、权限判定或 DAG 调度。金额、日期过滤、归并、余额状态全部由 `app/ledger_views.py` 的确定性代码完成；模型或解析器只能提出“想查看账本”的请求，不能生成或修改汇总数字。

当前演示只读取一个 Mock 演示账户，**不代表用户的全部资产**。生产替换点是经授权的核心账务、卡组织账单、账单导入与资金状态 Adapter。

## 2. 两种口径

### 消费视图

回答“我这个月花了多少”。规则是：

- 实际已完成的消费/订阅支出计入；
- 退款按退款发生的入账日期冲减消费，并单独展示退款金额；
- 本人转账不计入消费；
- 信用卡还款不计入消费；
- `processing`、`unknown`、冻结或预计到账的项目不当作已完成消费；
- 分类修正保留原始 `category`，新增 `corrected_category` 和修正记录，不覆盖原始流水。

### 账户资金流视图

回答“这张卡这个月流出了多少”。该口径展示本账户实际入账资金流出，包含信用卡还款，并明确标注：**包含还款，不等于消费**。本人转账属于账户资金流，但不是消费；退款作为资金流入单独列出。资金流视图同时返回 `outflow_cents`、`inflow_cents` 与 `net_outflow_cents`。

## 3. 跨来源归并

同一消费只有在来源明确提供 `canonical_id`、`original_transaction_id` 或 `linked_transaction_id` 时才去重。系统不会仅凭商户、金额和日期相同就猜测为同一笔，避免把两笔真实消费错误合并。

## 4. 资金状态分层

报告分开展示：

- `available_cents`：当前可用；
- `processing_cents`：处理中/结果尚待核验；
- `restricted_cents`：冻结、受限或卡片受限；
- `expected_arrival_cents`：预计到账但尚未入账。

这四类不合并成“总资产”。预计收入也不计入可用余额。数据覆盖范围和更新时间随报告返回，覆盖不足时使用“当前仅覆盖……不代表全部资产”的克制文案。

## 5. 四类问题与口径

| 用户问题 | 返回口径 | 可解释内容 |
|---|---|---|
| 我这个月花了多少 | 消费视图 | 总消费、退款、分类与明细 |
| 这张卡这个月流出了多少 | 账户资金流视图 | 流出、流入、净流出，并标注还款不等于消费 |
| 下周要准备多少钱 | 已确认待付款/到期义务 | 应从预算约束与订阅/账单数据单独计算，不把预计收入当余额 |
| 整体财务状况 | 只有覆盖充分时才回答 | 当前演示仅报告账户范围，不自称全资产 |

## 6. 生产替换点与诚实边界

- **核心账务**：替换 `MockBankCore.transactions` 与余额读取，使用银行核心的授权查询接口；生产需定义入账、冲正和资金状态一致性契约。
- **卡组织/信用卡账单**：提供账单周期、还款、退款与原始交易关联键。
- **账单导入服务**：提供来源标识和稳定的跨来源关联键，不能依赖商户金额日期猜重。
- **资金状态服务**：提供可用、处理中、冻结/受限、预计到账的服务端事实。
- **审计与权限**：生产仍由身份、权限、审计和数据最小化控制；本视图函数只读，不提供越权能力。

本实现是离线银行生产替身的演示能力，不连接真实银行核心，不宣称掌握全部资产或完成多机构账单接入。测试证据见 `tests/test_ledger_views.py`，T13 勾稽已同步为 A，但该 A 仅表示明确关联键去重的自动化证据。
