# T06 有限会话上下文

## 目标与实现范围

在现有 `IntentParser → Planner → PolicyEngine → confirm/verify → 工具` 主链上，补齐同一会话中未完成转账的收款人和金额。不增加运行时依赖，不接入 RAG，不把会话记忆作为授权或账户事实。

依据：`docs/用户投诉与需求研究报告.md:184` 的“上下文、省略信息”目标；`docs/安全设计与威胁模型.md:32` 的查询不能衍生写操作、`:38` 的模糊确认必须绑定计划；`docs/技术方案与项目管理总体设计.md:256` 的跨任务残留和隐私边界。本批采用受限演示实现，不宣称支持任意多轮对话。

## 可演示的流程

1. 输入 `我要转账`，系统询问收款人和金额。
2. 输入 `给妈妈`，系统继续询问金额。
3. 输入 `200元`，系统重新规划并展示“向妈妈转账 200 元”的确认卡；此时不扣款。
4. 核对卡片并点击确认后，才走原有工具执行链。金额超过现有阈值仍须强认证。

也支持 `转账200.01元 → 收款人是妈妈`。金额仍由现有规则解析为整数分。聊天可继续补充，原有“补充转账信息”表单仍可使用。

## 记忆与清理边界

| 项目 | 当前行为 |
|---|---|
| 支持内容 | 一个未完成转账草稿；仅收款人、整数分金额、开始时间和轮数 |
| 补充语法 | 单独金额（如 `200元`、`金额200元`）；已知演示收款人（如 `给妈妈`、`收款人是妈妈`） |
| 隔离键 | 服务端身份、设备、渠道、会话 ID 的元组；会话 ID 本身不授予权限 |
| Web 页面 | 每次打开页面产生独立随机会话 ID，其他标签页不继承草稿 |
| 有效期 | 从首条草稿起固定 300 秒，不因补充而续期；最多 3 条消息（含首次请求） |
| 容量 | 最多 256 个草稿会话槽；满时淘汰空闲槽，所有槽忙时新会话不保留上下文 |
| 网关映射 | 最多 1024 个会话映射，空闲 1800 秒后失效；元组键避免冒号拼接碰撞 |
| 清理时机 | 话题切换、无法识别的补充、注入/披露拦截、完整新任务、草稿补齐、进程重启；过期项在后续访问时清理 |
| 并发 | 同一隔离键串行处理，防止两条补充重复消费同一草稿；不同键分别处理 |

不记忆聊天原文、备注、账号、余额、工具结果、口令、验证码、确认 token 或认证凭据。含备注/显式账号、未核验收款人、非法金额的请求不进入此草稿记忆；家庭代理/受管理账户暂不启用，需要独立审查其授权契约。

`好的`、`确认`、`继续`、`再来一笔` 不会消费原计划的授权或自动重发。已展示的完整计划不通过后续片段修改，仍须按原来的 `plan_id + action_token` 确认。新的完整指令不会继承旧草稿的收款人或金额。歧义表达要求重新明确需求，不做猜测补全。

## 代码与验收依据

- `app/conversation_context.py`：有界内存、固定 TTL、轮数限制、按键串行、受限片段补全。
- `app/banking_agent.py::AgentRuntime.chat / _chat`：安全检查后使用草稿，重走现有规划和权限判定；`context.draft.applied` 只记录补全行为，不记录完整历史或凭据。`IntentParser._extract_beneficiary` 同步排除将“转账200元”的“账”误识别为人名。
- `app/channel_contracts.py`：设备绑定传递、渠道命名空间、元组会话键及映射容量/过期限制。
- `app/static/app.js`：页面独立会话 ID；可对话补充时不强制弹出表单，用户仍可主动打开表单。
- `tests/test_conversation_context.py`：补全、强认证、隔离、TTL、轮数、容量、并发、切换话题、注入、非法金额、重启与真实浏览器两标签页验证。
- `tests/test_d1_security.py`：真实 HTTP 的跨用户/会话隔离、伪造身份拒绝及补齐后的新确认流程。

复验命令：`python scripts/browser_qa.py --full`。查看本次实际生成的报告，不以本文中的功能说明替代通过记录。
