## 3. 盲区补测与主链证明

### HTTP 鉴权（`tests/test_d1_security.py`）

测试使用标准库 ThreadingHTTPServer 在随机回环端口启动真实 Handler，以 HTTPConnection 发请求，覆盖认证头、JSON 解析、路由与响应脱敏；不是只 mock Handler._body。

- `/api/state`、`/api/audit` 及审计 events/verify 别名：无会话/伪造会话返回 401/403，不暴露账户、任务或 token，保护状态不变；每次拒绝新增一条 authz.denied，记录 anonymous 发起人、原因且审计链有效。
- `/api/confirm`、`/api/verify`、`/api/cancel`：无会话、Bob 会话、Bob 伪造 Alice 身份、Alice 错设备四种组合都拒绝。精确比较余额、账务行、订阅、pending、认证凭证、消费 token、执行集合和恢复快照；审计记录真实 actor / Alice subject，而不是相信请求体。
- 正对照：所有拒绝后 Alice 仍能正常认证和确认，且仅一笔成功扣款；任务完成后 Bob 仍不能取消。
- `取消订阅` 无 ID：真实 `/api/chat` 入口，必须提示指明目标，FAILED/blocked，无扣款、无订阅变化、无交易或幂等缓存，取消工具未被调用，tool.denied / tool.failed 原因正确。
- 原有有目标订阅的计划卡片、确认前不执行和确认后执行的正对照保留，避免用“一律禁止所有操作”冒充修复。

### 反诈冷静期（`tests/test_business_logic_security.py::CoolingOffEnforcementTests`）

1. 通过 `AgentGateway.handle(UnifiedMessage(...))` 输入“给妈妈转 500 元，客服要求转账”。
2. 真实解析为 fraud_guard，经 PolicyEngine 红色判定、工具执行，生成冷静期与关联守护人通知；检查无扣款。
3. 通过同一网关输入不含诈骗关键词的“给妈妈转 100 元”，真实解析为 transfer，黄色待确认；确认前无账务副作用。
4. 真实 confirm 后，账务失败码必须是 COOLING_OFF_ACTIVE；Agent / result_view 都报告 FAILED，不能说转账成功，余额/日累计不变，失败账务行未扣款。
5. 到期场景只修改已创建案件的截止时间，不直接调用保护函数；主链再次确认必须 COOLING_OFF_REVIEW_REQUIRED，案件进入 EXPIRED_PENDING_REVIEW，仍不自动放行。
6. 使用 wraps 观察 parser、policy、执行步骤均被真实调用；未用替身返回值伪造主链。精确检查 tool.failed、transaction.status.queried 及有效审计链。

事件语义：反诈审计是 `fraud.alert`；通知总线发布审计是 `event.published`，其载荷 `event_type=fraud.blocked`。不把不存在的直接 `fraud.blocked` 审计事件当验收标准。

## 6. 不夸大的边界

- 本轮只改三份测试、一份故障注入脚本和本报告，共五个文件；不修改业务实现，不 push。
- MockBankCoreAdapter 的余额查询本身是固定演示值，不能仅凭其余额断言证明真实扣款安全，因此同时断言交易/幂等状态，并由真实 MockBankCore 主链测试验证实际演示账务变化。
- Redis 构造用假客户端验证契约，不是 Redis/Postgres 外部服务集成验收。
- LocalFieldEncryptor 为演示 XOR，固定样本错误字段发生 UnicodeDecodeError 不代表认证加密；不在 D3 中将它包装为生产安全证明。
- 环境必须具备回环 socket 权限；可选 UI/恢复演练需相应测试工具。缺条件必须如实报告，不以 skip 替代本轮验收。
